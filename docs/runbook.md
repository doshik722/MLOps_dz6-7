Продолжена Git-история ДЗ 5 (исходный коммит d61502a). Исправлены четыре дефекта MLflow и две функции оценки. Тесты преподавателя не изменены: общий отпечаток tests/ — c42ac7788026. Зависимости установлены через uv sync --frozen.

## Docker и MLflow

Docker Desktop установлен для текущего пользователя. MLflow должен работать по http://127.0.0.1:5006. База Postgres и файлы моделей имеют отдельные named volumes.

На первичной проверке Docker долго оставался в starting; после автоматической остановки по таймеру простоя возобновление также зависло. Выполнен перезапуск Docker/службы WSL без удаления дистрибутивов и volumes. На время подготовки таймер простоя Docker увеличен до 3600 секунд. Остановленная hns сама по себе не установлена как причина: корректность запуска проверяется готовностью Engine и HTTP /health MLflow.

## Выполнение в видимом терминале

Откройте терминал из корня hw67-broken. Makefile сам находит установленный Docker Desktop и Git Bash на Windows; не нужен фоновый запуск или просмотр отдельного журнала.

```bash
uv sync --frozen
make check-eval
make up
make sweep
make report
make candidate
make baseline-init
make evaluate
make eval
```

make sweep — шесть отдельных конфигураций по четыре шага с выводом в терминал; параметры не меняются по ходу поиска. baseline-init выполняется один раз и отказывается перезаписывать существующий baseline.

Если make eval вернул PASS:

```bash
make check-negative
make promote
```

Если make eval отказал в качестве, сохраните этот отказ. Выполните make check-negative, но не вызывайте make promote и не ослабляйте условия. Отказ — допустимый результат; alias candidate остаётся для приёмки хранения/загрузки.

Затем в обоих случаях:

```bash
make check-storage
make evidence
make check-all
```

После check-all можно ещё раз выполнить make evidence для упаковки актуальных JSON/Markdown/CSV. Он не обучает и не меняет alias. Исходные проверки выводят общий отпечаток tests/.

## Что показать преподавателю

Один ролик на 5–8 минут: 6 дочерних runs в MLflow, версии данных/кода и кривые; таблица comparison.csv; реестр candidate; baseline/candidate accuracy и срезы; 3 behavioral-кейса и diff; сохранённый отказ/принятие; отрицательная проверка; SHA256 probe после пересоздания; итог check-all и отпечаток. Часы обучения записывать не нужно.

Обязательные отчёты: docs/comparison.csv, docs/defects.md, один docs/conclusion.md. Сырые ответы и метрики находятся в metrics/ и отдельно пакуются make evidence в submission/results.zip. Данные проверки приложены в submission/evaluation-data.zip и версионируются через data.dvc.

## Вывод

Готовность исходников и unit-тестов не заменяет реальный sweep и оценку ответов. Итоговый вывод должен отражать фактические запуски и решение gate; отсутствующие результаты в отчёте явно помечаются.
